# Хатшы

**Команда:** № 019. MedHub HAQathon 2026, кейс UMC «Лист консультации по речи врача и пациента».

«Хатшы» по-казахски значит «секретарь».

## Проблема

Врач заполняет лист консультации вручную, во время приёма или после него. Время уходит на клавиатуру, а не на пациента. Готовые облачные сервисы расшифровки требуют отправлять разговор целиком, вместе с ФИО, ИИН и диагнозом. Для клиники это риск по закону о персональных данных и врачебной тайне.

## Решение

Врач разговаривает с пациентом как обычно. Хатшы записывает приём, распознаёт речь, сам заполняет лист консультации и после проверки врачом передаёт его в МИС. Распознавание речи и языковые модели работают на сервере клиники. В интернет не уходит ни один запрос.

### Как это работает

1. Врач выбирает себя. По специальности подставляется свой шаблон листа и свой словарь терминов. Сейчас есть терапевт и акушер-гинеколог.
2. Врач выбирает пациента из МИС и язык приёма: русский, казахский или смешанный.
3. Идёт запись приёма в браузере.
4. Сервер распознаёт речь (whisper.cpp, модель large-v3-turbo) с подсказкой из словаря специальности.
5. ФИО, ИИН, телефоны и адреса заменяются метками. Языковая модель видит только текст с метками.
6. Локальная модель (Ollama, qwen3:4b) раскладывает разговор по полям листа короткими запросами. К каждому полю приложена цитата из разговора.
7. Числа, даты, срок беременности, код МКБ-10 и проверку аллергий делает обычный код, а не модель.
8. Врач проверяет лист, правит поля набором или голосом и разбирает предупреждения.
9. Когда врач подтвердил диагноз, система показывает обследования из клинического протокола МЗ РК.
10. Лист уходит в МИС через API или скачивается в Word.

### Защита данных

- Звук приёма хранится и распознаётся только на сервере клиники.
- Перед обращением к модели текст маскируется: ИИН (в том числе продиктованный группами цифр), телефоны, почта, адреса, ФИО пациента и врача во всех падежах, другие имена.
- Если после маскирования в тексте остался ИИН или телефон, запрос к модели не выполняется.
- Адрес модели вне сети клиники отклоняется до отправки текста.
- Таблица замен лежит в базе клиники и на экране показывается в прикрытом виде.
- На экране «Контур данных» видно, какой текст получила модель и на какие адреса уходили запросы.

Проверить можно так: выключить Wi-Fi и записать новый приём. Всё продолжит работать.

### Защита от ошибок модели

- Модель получает правило «пиши только то, что прозвучало». Пустое поле остаётся пустым и помечается для врача.
- У каждого поля есть цитаты с временем. Фразу можно прослушать.
- Если в поле есть слова, которых не было в разговоре, поле помечается «проверьте».
- Показатель (давление, пульс, вес) принимается, только если в разговоре прозвучало его название. Иначе значение отбрасывается, что бы ни ответила модель.
- Запись об аллергии принимается, только если об аллергии говорили.
- Код МКБ-10 берётся из справочника. Если совпадение неточное, код не подставляется, врач выбирает сам.
- Срок беременности и предполагаемая дата родов считаются по формуле от даты последней менструации.
- Если назначен препарат из группы, на которую у пациента аллергия, лист нельзя отправить в МИС, пока врач не изменит назначение или не подтвердит его.
- На тишине модель распознавания выдумывает фразы из субтитров к видео. Такие фразы отбрасываются, а полностью тихая запись не обрабатывается.
- Если в записи есть участок без текста дольше восьми секунд, врач видит предупреждение и может прослушать это место.
- Сырой ответ модели хранится отдельно от правок врача.

### Казахская и смешанная речь

Стандартный whisper на казахском ошибается слишком часто, а маленькая языковая модель плохо понимает казахский текст. Поэтому для приёмов на казахском и смешанном языке цепочка другая:

1. Запись режется на фразы по паузам, каждая фраза распознаётся отдельно.
2. Казахские фразы распознаёт отдельная модель: whisper large-v3-turbo, дообученный на корпусе KSC2 (около 1000 часов казахской речи, ISSAI). Автор модели abilmansplus, лицензия MIT.
3. В смешанном приёме каждая фраза распознаётся обеими моделями. Если казахская модель услышала заметную долю казахских слов, берётся её вариант, иначе вариант стандартной модели на русском.
4. Казахские реплики переводятся на русский отдельным шагом (gemma3:4b) с медицинским словарём. Если в переводе остались казахские буквы, реплика переводится повторно по одному предложению.
5. Поля заполняются по русскому тексту. Врач видит под казахской репликой её перевод.

Сроки на казахском («бір аптадан кейін», «жұма күні») переводит в даты код.

### Диагностика по клиническим протоколам МЗ РК

Диагноз ставит врач. Когда он подтвердил код МКБ-10, система показывает обследования, которые записаны для этого диагноза в клиническом протоколе МЗ РК, и отмечает, что из них уже есть в листе. Недостающее врач добавляет в план одним нажатием. Лечение не подсказывается.

Модель здесь не участвует: перечни заранее выписаны из текста протокола в файлы `backend/protocols`, во время приёма работает только сравнение строк. У блока указаны название протокола, год, дата и номер одобрения и ссылка на текст.

| Протокол | Одобрен | Коды МКБ-10 |
|---|---|---|
| Острый и хронический тонзиллит, 2016 | 23.06.2016, № 5 | J03, J35.0 |
| Антенатальный уход, 2025 | 17.03.2026, № 248 | Z34, Z32.1, Z33, Z35, Z36 |
| Хронический холецистит, 2013 | 12.12.2013, № 23 | K81.1 |

Протокол по беременности расписан по восьми посещениям. Нужное посещение выбирается по сроку, который система считает из даты последней менструации.

## Запуск

### В Docker

Нужны Docker и Docker Compose.

```bash
./scripts/get_models.sh          # модель распознавания речи, 1,6 ГБ, один раз
./scripts/get_kazakh_model.sh    # модель для казахской речи, по желанию
cp .env.example .env
docker compose up --build
```

Интерфейс откроется на http://localhost:8080, демо-МИС на http://localhost:8100, описание API МИС на http://localhost:8100/docs.

При первом запуске сервис `model-pull` скачивает языковые модели. После этого интернет больше не нужен.

| Сервис | Что делает |
|---|---|
| `frontend` | интерфейс: React, TypeScript, nginx |
| `backend` | сервер: FastAPI, whisper.cpp, SQLite |
| `ollama` | локальные языковые модели |
| `model-pull` | один раз скачивает модели и завершается |
| `mis` | демо-МИС: пациенты и приём листов |

### Без Docker на Mac

На Mac модели внутри Docker работают без видеоускорения, поэтому для показа удобнее запускать напрямую.

```bash
brew install whisper-cpp ffmpeg ollama
ollama pull qwen3:4b
ollama pull gemma3:4b
uv venv --python 3.11 .venv
uv pip install --python .venv/bin/python -r backend/requirements.txt
(cd frontend && npm install && npm run build)
./run_local.sh
```

Приложение откроется на http://127.0.0.1:8000.

### Переменные окружения

Секретов нет. Все переменные описаны в `.env.example`:

| Переменная | Назначение |
|---|---|
| `WHISPER_MODELS_DIR` | папка с моделями распознавания речи |
| `LLM_MODEL` | языковая модель для заполнения полей |
| `LLM_MODEL_KK` | модель для перевода казахских реплик |
| `OLLAMA_MODELS_DIR` | папка с уже скачанными моделями Ollama, по желанию |
| `MIS_URL` | адрес МИС клиники |
| `HATSHY_ORG` | название клиники для шапки листа в Word |

## Структура проекта

```
backend/
  main.py         сервер и API
  pipeline.py     весь путь одной записи
  asr.py          распознавание речи, казахская и смешанная речь, исправление терминов
  mask.py         маскирование персональных данных
  llm.py          обращение к локальной модели и журнал запросов
  extract.py      перевод реплик и раскладка разговора по полям
  calc.py         показатели, срок беременности, МКБ-10, проверка назначений
  dates.py        перевод устных сроков в даты, русских и казахских
  protocols.py    диагностика по клиническому протоколу
  export_docx.py  лист в Word
  templates/      шаблоны специальностей
  protocols/      клинические протоколы МЗ РК
  refdata/        справочники: МКБ-10, аллергии, словари
frontend/         интерфейс на React и TypeScript
mis/              демо-МИС
scripts/          загрузка моделей, замер точности, загрузчик протоколов
samples/          сценарии тестовых приёмов и эталоны для замера
docs/             демо-видео и снимки экранов
```

Шаблон специальности это один файл в `backend/templates`: поля листа, словарь для распознавания речи и порядок запросов к модели. Новая специальность добавляется новым файлом. Новый протокол тоже добавляется одним файлом, формат описан в `backend/protocols/README.md`.

Проверка цепочки из командной строки и замер точности по эталонам:

```bash
./samples/make_samples.sh
cd backend && ../.venv/bin/python pipeline.py ../samples/therapist_1.wav therapist ru "Нурланова Айгерим"
cd .. && .venv/bin/python scripts/evaluate.py
```

Эталон это список фактов по полям листа (`samples/gold/*.json`), его готовит врач.

## Что готово

### Реализовано

- выбор врача и специальности, два шаблона листа: терапевт и акушер-гинеколог;
- выбор пациента из МИС или ручной ввод, выбор языка приёма;
- запись приёма в браузере или загрузка готового файла;
- распознавание русской, казахской и смешанной речи на сервере клиники;
- маскирование персональных данных и экран «Контур данных»;
- заполнение полей листа локальной моделью, цитата к каждому полю;
- проверка и правка листа врачом, в том числе голосом;
- код МКБ-10 из справочника, расчёт срока беременности и даты родов;
- предупреждение об аллергии на назначенный препарат;
- диагностика по клиническим протоколам МЗ РК;
- передача листа в МИС через API, выгрузка в Word;
- история приёмов и счётчик полей, принятых без правок;
- упаковка в Docker Compose.

### Что измерено

На MacBook Pro M3 Pro, 18 ГБ:

| Запись | Длительность | Обработка без Docker | Обработка в Docker |
|---|---|---|---|
| приём у терапевта | 86 с | около 30 с | 92 с |
| приём у акушера-гинеколога | 102 с | около 42 с | не измеряли |
| длинная запись | 8 мин | 3,5 мин | не измеряли |
| живой приём на русском | 23 с | около 20 с | не измеряли |

Точность по эталонам на двух синтезированных приёмах: 27 полей из 27, 61 факт из 61, выдумок 0. Эти записи синтезированы голосом компьютера по сценарию, поэтому цифра показывает только, что цепочка не ломается. На живой речи точность не измерена: нет эталонных листов от врача.

### Известные ограничения

- Текст появляется после завершения приёма, а не во время него.
- Говорящие не разделяются по голосу. Роли расставляет модель по смыслу фраз, врач может поправить.
- Короткие ответы пациента на вопросы врача («Было», «Сорок») модель не всегда связывает с вопросом. Такие сведения врач дописывает сам.
- Казахская речь проверена на трёх коротких живых записях. Переключение языка внутри одной фразы распознаётся хуже всего, названия лекарств в казахской речи модель может исказить, перевод делает небольшая модель, и врач должен его проверять.
- Имена третьих лиц в казахских репликах не маскируются: библиотека поиска имён обучена на русском.
- Docker-сборка проверена до добавления казахской цепочки, после неё не пересобиралась.
- Нет входа по паролю и разграничения прав.
- Подключена демо-МИС, а не настоящая.
- Пациенты и врачи в демо-данных вымышлены.

### Что должен проверить врач

Эти файлы заполнены как черновик и помечены `verified_by_doctor: false`:

- перечни обследований в `backend/protocols`;
- `backend/refdata/allergy_groups.json`: группы препаратов для проверки аллергий;
- `backend/refdata/pregnancy_drugs.json`: препараты, нежелательные при беременности;
- `backend/refdata/icd_aliases.json`: соответствие частых формулировок кодам МКБ-10;
- `backend/refdata/kk_glossary.json`: казахско-русский медицинский словарь;
- словари и поля в `backend/templates`.
